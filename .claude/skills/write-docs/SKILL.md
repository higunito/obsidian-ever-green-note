# スキル：ドキュメント作成

`docs/` と `tmp/` の設計・仕様・計画文書を書く／更新する手順。`.claude/rules/documentation.md` を必ず守る。

## 手順

1. **対象文書の役割を確認する**
   - design（設計）／specification（画面仕様）／implementation-plan（実装計画）のどれを書くかを確定し、役割を混ぜない。

2. **既存文書と参考資料を読む**
   - 該当箇所と関連文書を読み、**既にある事実は転記せず参照（相対リンク）**する。
   - コンテンツ契約に関わる内容は `reference/obsidian/README.md` と矛盾しないか確認する。

3. **書く**
   - 日本語・既存の見出し様式に合わせる。**曖昧さを排除**し、実装者ごとの差が出ない粒度で書く。
   - 用語は design §13、ゲーム内名称は design §3.3 の対応表に従う。

4. **整合を取る（仕様変更時）**
   - 変更は **design → specification → implementation-plan の順に波及**させる。
   - 旧記述・旧名称が残っていないか `grep` で洗い出し、全箇所を更新する。

5. **仕上げ**
   - 各文書末尾の **変更履歴に追記**する。
   - 相互リンクのアンカー切れ・lint 警告（markdownlint 等）を確認する。

## チェックリスト

- [ ] 文書の役割を守っているか（設計に手順を、仕様に実装詳細を混ぜていないか）
- [ ] 同じ事実を複数箇所に重複させていないか（DRY・参照で済ませる）
- [ ] 名称・用語が design の正典表記と一致しているか
- [ ] 関連文書との齟齬がないか（grep で確認）
- [ ] 変更履歴を更新したか
